# Project: Semantic-to-Relational Hardener (Local CLI)

## 1. System Overview
This is a high-performance, zero-allocation C# .NET 10.0 command-line application. Its purpose is to ingest streaming JSON-like semantic tokens generated by a local LLM, validate them instantly against a strict database schema using an in-memory state machine, and stream the validated records directly into a relational database at maximum throughput.

## 2. Hard Constraints (DO NOT VIOLATE)
*   **NO ORMs:** Entity Framework, Dapper, or any other data access frameworks are strictly forbidden. You will use raw ADO.NET (`Microsoft.Data.SqlClient` and `Npgsql`) exclusively.
*   **Zero-Allocation Data Path:** The hot path (reading tokens, parsing strings, validating types, and preparing DB inserts) must allocate ZERO memory on the managed heap.
*   **Memory Primitives:** You must use `ReadOnlySpan<char>`, `Span<byte>`, `Memory<T>`, `ArrayPool<T>`, and `ref struct` types for all data manipulation.
*   **Garbage Collection:** The GC must not pause during the ingestion loop. Avoid `string.Substring`, string concatenations, or allocating new arrays inside loops.
*   **No Third-Party Bloat:** Do not install mapping libraries (like AutoMapper) or DI container frameworks. Keep the dependency graph as close to zero as possible.

## 3. Architecture & Interfaces

### The Schema Validator
Create a highly optimized, memory-resident representation of the target database schema. 
*   Implement a Trie or custom state machine to rapidly match incoming token streams to table column names using `ReadOnlySpan<char>`.
*   Implement strict type coercion (e.g., parsing a span of chars into an `int` or `DateTime` without allocating strings). If coercion fails, the record is flagged and dropped.

### The Ingestion Engine
*   Implement a buffered `System.IO.Pipelines` reader to asynchronously read the incoming data stream from standard input (stdin) or a named pipe.
*   The parser must slice the `ReadOnlySequence<byte>` directly and pass the spans to the Schema Validator.

### The Relational Sink (ADO.NET)
Create a provider-agnostic sink using the following interface:
`public interface IRelationalSink : IAsyncDisposable`
`{`
`    Task InitializeAsync(string connectionString, string targetTable);`
`    Task WriteRecordAsync(ReadOnlySpan<char> columnData, ReadOnlySpan<char> valueData);`
`    Task FlushBatchAsync();`
`}`

*   **SqlServerSink:** Implement using raw `SqlBulkCopy`. Buffer validated rows into memory-pooled arrays and flush them to SQL Server in batches of 10,000.
*   **PostgresSink:** Implement using `NpgsqlBinaryImporter` for high-performance bulk binary streaming directly into PostgreSQL.

## 4. Execution Flow
1. The CLI starts, parsing arguments for target DB (SQL/PG), connection string, and target table.
2. The CLI connects to the target DB and dynamically generates the in-memory schema rules via `sys.columns` or `information_schema.columns`.
3. The CLI listens to standard input (stdin) for incoming data.
4. Data is parsed via `System.IO.Pipelines`, validated via spans, mapped to the correct columns, and buffered.
5. Buffers are flushed asynchronously using native bulk-copy operations.
