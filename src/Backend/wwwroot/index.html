Command Line Reference

To run the compiled self-contained AOT binary, pass the target database engine, schema table, and optional file path parameters:

Glacier.Forge --db <sqlserver|postgres> --table <schema.table_name> [--file <file_path>]

Parameters

Flag Required Values Description
--db Yes sqlserver, postgres Relational database engine mapping target.
--table Yes String (e.g., dbo.users) Table name. For Postgres, qualify it with a schema (e.g. public.users).
--file No File path Ingests a local .jsonl file. If omitted, streams via stdin.

JSONL Formatting & Schema Rules

Each line must contain a single JSON Object. Below are the precise validation behaviors of the zero-allocation parser:

  • Case-Insensitive Column Matching: Incoming JSON properties are matched against the target table's database schema columns via a high-performance Trie. userId, userid, and USERID are all successfully resolved to the database column UserId.
  • Nested Structures Tolerated: If properties contain arrays or sub-objects, the engine calls reader.Skip() to safely skip them without loading or allocating memory, ensuring stability against arbitrary JSON.
  • Null Handling: Missing properties or explicit null tokens (e.g., "email": null) are automatically mapped to database NULL values.
  • Superfluous Properties: Extra keys present in the JSON line that do not exist in the database table schema are automatically skipped.

Ingestion Pipeline Workflows

1. Real-Time Streaming via Standard Input (stdin)

Stream live non-deterministic logs or generated outputs directly from a scripting environment into a secure PostgreSQL table:

python generate_llm_records.py | Glacier.Forge --db postgres --table public.raw_logs

Note: Forge buffers inputs in-memory and automatically flushes them in chunks of 1,000 to keep the transactional load low.

2. Mass File Ingestion (Hybrid I/O)

Ingest a local static backup file. Forge automatically selects the optimal loading strategy based on file size:

Glacier.Forge --db sqlserver --table dbo.billing_history --file C:\backups\data.jsonl
  • < 1MB: Rented array buffers from ArrayPool<byte> are utilized.
  • ≥ 1MB: Utilizes a MemoryMappedFile pointer to map raw bytes directly to memory, enabling copy-free loading for gigabyte-scale streams.

License Key Activation

Glacier.Forge requires a valid ECDSA signature key to initiate the engine. You can configure this in one of two ways:

Option A: Environment Variable (Recommended for Docker/App Runner)

Set the GLACIER_LICENSE environment variable to your base64-encoded signature key:

# PowerShell
$env:GLACIER_LICENSE="<base64_payload>.<base64_signature>"

# Shell (Linux/macOS)
export GLACIER_LICENSE="<base64_payload>.<base64_signature>"

Option B: Local License File

Place a file named license.lic directly in the directory of the executing application binary containing the license key:
