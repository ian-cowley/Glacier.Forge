Ecosystem Flagships

The foundational pillars powering modern zero-allocation .NET workloads

Flagship #1 • Analytics

Glacier.Polaris

The lightning-fast, strongly-typed C# DataFrame engine inspired by Python Polars.

Combines columnar in-memory architecture, AVX-512 / ARM Neon SIMD vectorized kernels, lazy execution graphs, and zero-copy Arrow integration to bring modern high-performance data manipulation to the .NET ecosystem.

  • Vectorized filtering, grouping, aggregation, and multi-threaded joins
  • Zero GC allocations on vectorized arithmetic loops
  • T-SQL query layer integration via Glacier.Sql
Star Glacier.Polaris
Flagship #2 • Ingestion

Glacier.Forge

The zero-allocation Semantic-to-Relational Hardener for high-velocity streaming.

Bridge the gap between unpredictable LLM outputs and strict relational schemas. Slices UTF-8 JSONL streams with Utf8JsonReader, validates columns via a byte-space Trie in $O(L)$ time, and bulk-loads directly into PostgreSQL binary COPY and SQL Server SqlBulkCopy at 146μs speeds with 0-byte GC allocations.

  • Zero-copy Hybrid I/O: RandomAccess + Memory-Mapped Files
  • PostgreSQL Binary COPY & SQL Server custom PooledBatchDataReader
  • 100% Free & Open Source (MIT)

Glacier.Forge Quickstart Guide

Zero-allocation streaming ingestion into SQL Server & PostgreSQL

Command Line Reference

Glacier.Forge runs as a high-performance native CLI tool or standard .NET 10 console application:

Glacier.Forge --db <sqlserver|postgres> --table <schema.table_name> [--file <file_path>] [--map <aa:ll,bb:kk>]

Parameters

Flag Required Values Description
--db, -db Yes sqlserver, postgres, pg Relational database engine mapping target.
--table, -t Yes String (e.g. dbo.users or public.raw_logs) Destination table name with optional schema.
--file, -f No File path Ingests a local .jsonl file. If omitted, streams via stdin.
--conn, -c No Connection String Direct connection string (falls back to appsettings.json / user-secrets).
--map, -m No Comma-separated pairs Maps non-matching JSON property names to target database column names dynamically.

JSONL Formatting & Schema Validation

Each line must contain a single JSON Object. Below are the precise validation behaviors of the zero-allocation parser:

  • Byte-Space Trie Matching: Incoming JSON properties are matched against target database columns in $O(L)$ time with ASCII bit-shift case insensitivity.
  • Nested Structures Tolerated: If properties contain arrays or sub-objects, reader.Skip() traverses them without allocating memory.
  • Automatic Null Handling: Missing properties or explicit null tokens are mapped directly to database NULL values.
  • Supported Data Types: Full native support for int, smallint, bigint, uuid/guid, bool, datetime, date, float, decimal, json, and varchar/text.

Streaming Ingestion Examples

1. Real-Time Streaming via Standard Input (stdin)

python generate_llm_records.py | Glacier.Forge --db postgres --table public.raw_logs

2. Mass File Ingestion (Hybrid I/O)

Glacier.Forge --db sqlserver --table dbo.billing_history --file C:\backups\2026_data.jsonl
  • < 1MB: Rented array buffers from ArrayPool<byte> and OS RandomAccess.
  • ≥ 1MB: Direct MemoryMappedFile pointer with line-aligned boundary chunking.
